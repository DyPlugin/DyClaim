# DyClaim 1.0.3

## Added

- A separate Folia backend with native region and entity scheduling. The standard build continues to target Bukkit, Spigot, Paper and Purpur.
- Joined nearby outlines for side-connected claims with the same primary owner, hiding internal chunk edges while retaining bounded rendering.
- Optional name, world and sale-status filters for `/claim list`, with English/Turkish TAB suggestions and unchanged teleport indices.
- A personal effective-access summary and remaining temporary trust duration in `/claim info`.
- `/claim admin diagnose` for a short console/player support summary without credentials or filesystem paths; Turkish aliases `tanı` and `tani`.

## Changed and fixed

- Version labels and new artifact names use `1.0.3` without a `v` prefix. Historical releases remain unchanged.
- Update selection recognizes the new standard/Folia filenames and Folia version suffix while retaining historical filename compatibility.
- Region ownership, pending acquisition reservations, confirmation revalidation, lifecycle cancellation and concurrent persistence are coordinated for the Folia backend.
- Optional Vault absence no longer prevents startup through an eagerly bound provider method reference.
- Temporary block borders are read and restored on their own region; Java outline sampling rotates within the existing particle budget.

## Upgrading

Back up the existing JAR and complete `plugins/DyClaim` directory, stop the server, and replace its JAR with **one** 1.0.3 backend. Keep the data directory. Schema 2, existing commands/aliases, configuration and custom EN/TR messages are retained. Missing shipped message keys receive defaults.

Velocity/BungeeCord experimental companions are not included. See [platform requirements](../platforms.md) and [verification evidence](../verification-1.0.3.md) for actual tested scenarios and limitations.
